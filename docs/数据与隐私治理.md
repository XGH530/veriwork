# 数据、法源与隐私治理

## 数据分层

1. `data/evaluation_cases_v1.json`：80条开发回归样本，用于规则开发、消融和功能回归。
2. `data/holdout_cases_v1.json`：32条早期留出样本，暴露问题后已用于一次规则强化，不再视为独立盲测。
3. `data/holdout_cases_v2_frozen.json`：40条冻结留出样本，创建后不再根据结果调规则。
4. 真实用户材料：在获得明确授权和完成去标识化前，不进入公开仓库和演示视频。

## 来源原则

- 法律条文优先使用全国人大法律法规数据库。
- 人社政策优先使用人力资源和社会保障部及各地人社部门官网。
- 每个动态政策必须记录适用范围、生效日期、原文链接和核验时间。
- 未找到可靠来源时，系统应提示“待核实”，不得输出确定数字或法条。

## 个人信息保护

- 原始合同默认不长期保存，用户主动确认后才允许写入案例库。
- 演示材料必须删除姓名、电话、身份证号、公司内部信息和其他可识别信息。
- 大模型调用前明确告知用户数据可能离开本地环境，并提供纯本地规则降级模式。
- 支持删除、导出和保存期限设置，生产环境使用传输加密、权限最小化和审计日志。
- 竞赛公开材料不得包含任何真实用户原始合同。

## AI 使用披露

应记录模型名称、版本、服务提供方、调用日期、提示词版本、使用环节、生成内容、人工筛选与修改过程，以及团队原创贡献。模型不得被描述为法律结论的最终责任主体。
