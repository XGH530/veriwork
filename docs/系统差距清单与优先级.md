# 职安盾 VeriWork 系统差距清单与优先级

截至2026年10月12日，系统已经可以完成完整演示：材料输入、风险规则、语义识别、大模型候选、法源绑定、证据链和评测展示。距离“成熟产品”仍有以下差距。

## 一、必须补齐的参赛证据

这些缺口直接影响省赛评分，优先级最高。

| 缺口 | 当前状态 | 影响 | 截止前做法 |
|---|---|---|---|
| 真实用户测试 | 尚未完成 | 无法证明真实可用性 | 找20名高校学生，记录使用前后风险识别、耗时和满意度 |
| 外部抽样复核 | 尚未完成 | 法律专业性不足 | 先找学校法务、法律援助中心和法学教师；找不到就采用双人标注加第三人仲裁 |
| 地方政策核验 | 仍为草案 | 地方标准不能用于正式结论 | 人社部门官网核验北京、上海、广东，填写生效日期和来源 |
| 演示视频 | 尚未录制 | 提交材料不完整 | 录制3分钟稳定演示和5分钟完整演示 |
| 团队正式信息 | 仍为占位符 | 报名和证书信息必须准确 | 填写成员、指导教师、第一申报单位和学校 |

## 二、产品功能缺口

这些不影响最低提交，但会影响“完整产品”观感。

### 1. 文件处理

当前主要支持粘贴文本和纯文本文件，缺少：

- PDF合同解析；
- DOCX和图片OCR；
- 表格、聊天截图和工资条识别；
- 多文件材料合并分析。

移动与网络应用赛项要求可运行版本和真实功能演示，支持合同文件上传会明显增强完成度。

### 2. 数据持久化

当前案例没有真正的用户账户和数据库，缺少：

- 登录和身份验证；
- 历史案例保存；
- 案例状态和办理进度；
- 用户删除和导出数据；
- 多设备同步。

答辩演示不依赖这些，但“产品化”叙事需要说明未来架构。

### 3. 证据材料管理

当前证据链以清单和文字为主，缺少：

- 实际上传证据文件；
- 文件哈希和完整性校验；
- 证据时间戳；
- 分类归档；
- 批量导出证据包。

### 4. 报告导出

当前可以下载文本报告和打印页面，缺少：

- 标准PDF研判报告；
- Word格式材料；
- 带编号和批注的合同对照版；
- 证据目录和材料封面。

### 5. 知识库更新

当前法源和规则是内置数据，缺少：

- 法规版本管理；
- 地方政策自动更新；
- 失效提醒；
- 人工审核工作流；
- 新规则灰度发布。

### 6. 检索能力

当前检索以规则映射和关键词排序为主，缺少：

- 向量检索；
- BM25与向量混合检索；
- 条文适用条件过滤；
- 引用冲突检测；
- 检索结果去重和重排。

### 7. 模型稳定性

当前依赖OpenAI-compatible接口，缺少：

- 多模型自动降级；
- 调用超时和重试策略；
- 成本统计；
- 输出缓存；
- 模型版本记录；
- 对模型超时和限流的可视化提示。

## 三、部署与安全缺口

正式上线前必须解决：

- 公网HTTPS部署；
- API密钥只保存在服务端；
- 用户同意和隐私说明；
- 上传文件大小、类型和病毒扫描；
- 数据加密和保存期限；
- 角色权限和审计日志；
- 删除请求和导出请求；
- 限流、防滥用和成本控制。

当前本地原型不涉及这些全部问题，但答辩时必须说明这是原型阶段的安全边界。

## 四、评测与研究缺口

当前评测全部为团队合成数据，缺少：

- 经授权的匿名真实合同样本；
- 法律实务人员盲测；
- 普通用户与系统对照实验；
- 置信度校准；
- 系统性错误分类；
- 统计显著性和置信区间；
- 不同模型重复运行稳定性。

现有40条冻结留出集可以证明开发流程，但不能等同于真实用户准确率。

## 五、界面体验缺口

当前界面已经改为正式工作台风格，但仍可继续完善：

- 增加真实合同文件处理流程，而不是只粘贴文本；
- 风险条目增加展开批注和法规原文；
- 证据链增加文件上传和状态追踪；
- 评测页增加可视化图表；
- 首页增加最近案例和待办事项；
- 移动端进一步适配；
- 增加打印版报告样式。

## 七、最重要的判断

当前系统的主要短板不是“页面还不够漂亮”，而是：

1. 没有真实用户使用证据。
2. 没有外部或替代法律复核。
3. 地方政策仍是草案。
4. 没有标准文件上传和报告导出。
5. 没有真正的数据持久化和部署安全。

省赛前只补前四项，部署安全放在作品说明和未来规划中，不要临时重构整个系统。
