# 职安盾 VeriWork｜零基础系统说明书

这份说明假设你完全不懂代码。你只需要先理解一句话：

> 职安盾是一个帮助毕业生检查就业合同风险的网页系统。它不会只给一句“有问题”，而是展示风险原文、法律依据、可信过程、证据清单和下一步行动。

## 一、系统到底解决什么问题

用户上传或粘贴一段劳动合同、Offer、实习协议后，系统会：

1. 找出“放弃社保、入职押金、培训贷、试用期低薪、无偿加班、竞业限制过长、离职违约金”等风险。
2. 指出风险对应的合同原文。
3. 给出对应的法律依据和风险原因。
4. 告诉用户下一步应该问HR什么、保存什么证据。
5. 生成事件时间线、沟通问题、投诉和仲裁材料草稿。
6. 在信息不足时提示“待核实”，不强行给确定结论。

它不是律师，也不能替代仲裁机构或人社部门。

## 二、系统由三部分组成

### 1. 前端

前端就是你在浏览器里看到的页面，文件是：

- `index.html`
- `styles.css`
- `data.js`
- `app.js`

前端负责显示工作台、风险报告、证据链和评测页面。即使不启动后端，也可以直接双击 `index.html` 演示。

### 2. 后端

后端文件是 `server.py`。它负责：

- 接收合同文本。
- 运行规则、语义识别和法源检索。
- 在配置了大模型时调用模型。
- 校验模型是否引用了真实原文和合法风险ID。
- 向前端返回统一结果。

后端不需要安装第三方Python库。

### 3. 大模型

大模型不是必须预先配置。系统中有一个安全开关：

- 不配置模型：使用规则、语义和法源检索，能够完整演示。
- 配置模型：模型可以在13类风险ID内提出有原文依据的候选风险，并补充解释。
- 模型输出没有原文依据、置信度低或风险ID非法时，系统会丢弃该输出。

配置方法是复制 `.env.example` 为 `.env`，填写模型地址、密钥和模型名称。

## 三、你现在怎么打开系统

### 最简单的方法

1. 打开项目文件夹。
2. 双击 `启动前端演示.bat`。
3. 浏览器打开页面。
4. 点击右上角“载入风险样例”。
5. 页面跳转到合同研判后，点击“运行可信研判”。
6. 查看风险分、风险清单、条款定位、可信轨迹和证据链。

如果 `.bat` 被系统拦截，直接双击 `index.html` 也可以。

### 启动完整服务

1. 确保电脑安装了Python。
2. 双击 `启动完整服务.bat`。
3. 浏览器打开 `http://127.0.0.1:8000`。
4. 此时前端会自动切到“后端API模式”。

## 四、页面逐个说明

### 1. 工作台

这里用于展示：

- 系统支持多少风险规则和法源。
- 有哪些演示案例。
- 可信运行状态。
- 从材料上传到行动建议的六步流程。

答辩时先展示这一页，说明项目不是普通法律聊天，而是可信风险决策系统。

### 2. 合同研判

这是核心页面。

- 左侧粘贴合同文字或载入文本文件。
- 选择材料类型和适用地区。
- 点击“运行可信研判”。
- 右侧显示风险分、风险数量、风险清单。
- 点击“条款定位”查看具体原文。
- 点击“可信轨迹”查看规则、检索、模型和拒答过程。
- 点击“生成研判报告”下载文本报告。

### 3. 证据链

这里把风险转成行动：

- 勾选已经保存的证据。
- 查看证据完整度。
- 查看事件时间线。
- 查看与HR沟通的问题。
- 查看投诉或仲裁材料草稿。
- 导出证据时间线。

### 4. 可信评测

这里说明系统如何被验证：

- 80条开发回归集。
- 32条早期留出集。
- 40条冻结留出集。
- 风险精确率、召回率、F1、法源覆盖率和待核实召回率。

注意：开发集分数高不代表真实用户准确率高。冻结留出集才是更保守的泛化结果。

### 5. 系统说明

这里解释：

- 六层可信研判链。
- 规则、法源、大模型和校验器分别做什么。
- 隐私保护原则。
- AI使用说明。
- 技术路线。

## 五、你们答辩时应该怎么讲

### 30秒版本

“职安盾不是法律聊天机器人，而是一套面向就业合同的可验证AI风险评估和证据链系统。规则负责硬约束，法源检索负责依据，大模型负责长尾语义，校验器负责阻止模型捏造。系统最终把风险转化为证据清单和行动材料。”

### 三分钟版本

1. 先介绍通用大模型在高风险场景中的不可信问题。
2. 展示六层可信研判链。
3. 载入风险合同并运行研判。
4. 展示一条风险的原文、法源、原因和行动建议。
5. 展示可信轨迹中的规则、检索、模型和拒答。
6. 展示证据链和时间线。
7. 展示开发集和冻结留出集结果。
8. 最后说明未来接入多模型对照和真实用户测试。

### 评委问“你们做了什么”

可以回答：

- 团队定义了风险类别、标签和评测方法。
- 团队开发了规则、前后端和证据流程。
- 团队构建了数据集、评测脚本和政策包治理结构。
- 大模型用于候选语义识别和解释，不拥有最终决策权。
- 所有模型输出都要经过原文和法源校验。

不要回答“整个系统都是大模型自动生成的”。

## 六、当前系统还不是什么

当前系统还不是：

- 正式上线产品。
- 律师服务。
- 经过权威机构认证的法律判断系统。
- 已服务大量真实用户的产品。
- 已完成地方最低工资自动更新的系统。

当前地方政策包是结构完整的草案，具体数值必须通过官方来源核验后填入。不能用未经核验的数字作为正式风险结论。

## 七、提交前必须由团队接手的三件事

### 1. 接入真实大模型

使用 `.env` 配置至少两个模型，运行：

```bash
python tools/evaluate_llm.py --dataset data/holdout_cases_v2_frozen.json --model 模型名 --api-url 模型地址 --api-key-env LLM_API_KEY --output-prefix 模型名_veriwork
```

### 2. 完成真实用户测试

至少找20名大学生，记录使用前后用时、漏检、误判、满意度和是否愿意继续使用。

### 3. 核验真实政策

从人社部门和全国人大法律法规数据库找到官方原文，填写到 `data/jurisdiction_policy_pack_v1.json`，执行：

```bash
python tools/validate_policy_pack.py
```

## 八、最重要的边界

你们可以展示系统强大，但不能说：

- “系统保证法律结论正确。”
- “系统可以替代律师。”
- “模型自己会判断所有风险。”
- “开发集100%就代表真实准确率100%。”
- “我们已经服务了大量真实用户。”

真正可控的表述是：

> 职安盾把高风险场景中的AI决策拆成规则、语义、法源、校验和行动五部分，让风险结论有依据、有原文、有边界，也能在信息不足时拒绝给出确定答案。
