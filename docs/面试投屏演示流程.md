# 职安盾 VeriWork 面试投屏演示流程

## 一、面试前 10 分钟检查

- 使用电脑端 Chrome 或 Edge。
- 浏览器缩放设置为 90% 或 100%。
- 关闭微信、QQ、邮箱和系统弹窗。
- 提前登录一个正常用户账号，不要展示管理员密码。
- 打开页面：http://8.133.222.0/veriwork/
- 准备一段演示合同文本，也可以直接使用“载入风险样例”。
- 准备一个备用方案：如果模型接口不稳定，改成纯前端演示模式，重点展示规则、法源和证据链。
- 不要展示 `.env`、API密钥、服务器终端或用户数据库。

## 二、一分钟开场

建议照着说：

“职安盾 VeriWork 是一个面向高校毕业生、初入职场人群和灵活就业人员的就业权益与政策服务平台。它不是法律问答工具，而是把合同风险核查、就业政策匹配和可信证据链连接起来，覆盖签约前、入职后和发生纠纷三个阶段。”

“项目的核心问题是：通用大模型虽然能回答问题，但在就业合同这种高后果场景里，存在法条引用错误、结论不可追溯、信息不足仍强制回答的问题。所以我把系统设计成规则优先、模型辅助、人工复核的可信链路。”

## 三、需求理解

### 用户是谁

- 高校毕业生；
- 初入职场人群；
- 灵活就业人员；
- 高校就业服务人员；
- 平台运营和后台管理人员。

### 用户真实痛点

1. 看合同看不出风险；
2. 知道风险，不知道该保存什么证据；
3. 不知道能申请什么就业政策；
4. 通用大模型回答不可追溯；
5. 发生纠纷后不知道如何整理材料。

### 产品目标

- 签约前：发现合同风险；
- 入职后：匹配就业政策；
- 发生纠纷：整理证据和行动材料；
- 对运营方：提供用户管理和风险统计。

## 四、AI实现

### 1. 规则层

先把规则明确的事项交给确定性程序：

- 试用期期限；
- 试用期工资；
- 社会保险；
- 入职押金；
- 培训贷；
- 工资支付；
- 加班费；
- 竞业限制；
- 离职违约金；
- 就业歧视。

规则层负责硬约束，不交给大模型自由决定。

### 2. 语义层

规则无法覆盖的表述交给语义匹配，例如：

- 工装费；
- 毕业证原件；
- 技能提升贷款；
- 合同中的否定表达；
- 实习、兼职和项目合作等模糊关系。

### 3. 大模型层

大模型负责：

- 识别长尾表达；
- 解释条款风险；
- 生成沟通问题和材料草稿。

大模型不能：

- 修改风险等级；
- 新增不存在的法条；
- 在没有原文依据时新增风险。

### 4. 法源层

每条风险绑定公开法规和政策来源，当前包含：

- 劳动法；
- 劳动合同法；
- 社会保险法；
- 就业促进法；
- 人社部门最低工资和政策信息。

### 5. 文件解析

系统支持：

- PDF；
- Word；
- 文本；
- 中文、英文、日文；
- PDF页码范围选择。

### 6. 评测

当前有：

- 80条开发回归集；
- 32条早期留出集；
- 40条冻结留出集；
- 两个DeepSeek模型公平对照；
- 风险精确率、召回率、法源覆盖率和待核实召回率。

## 五、人类负责什么

这是面试官最关心的一点，要主动讲清楚：

1. **人类定义规则边界**：系统识别什么、不识别什么，由团队决定。
2. **人类审核法源**：法规来源、版本、生效日期和适用地域由人核验。
3. **人类抽样复核**：抽取案例检查风险分类、漏检、误判和法源适用。
4. **人类处理不确定事项**：信息不足时进入待核实，不能由模型强行下结论。
5. **人类做最终行动决定**：系统只提供风险提示和材料整理，不替代律师、仲裁或人社部门。
6. **人类负责隐私和合规**：用户授权、数据保存期限、脱敏和删除权由平台运营方控制。
7. **人类评估模型效果**：通过回归集、留出集和对照实验决定是否上线更新。

一句话总结：

> 大模型负责理解和解释，程序负责硬规则和校验，人负责规则边界、法源准确性、最终判断和真实业务责任。

## 六、投屏演示完整顺序

### 第1步：登录界面

打开：

http://8.133.222.0/veriwork/

说明：

- 这是统一平台登录入口；
- 系统根据账号角色自动进入用户端或管理端；
- 密钥只保存在服务器端，不进入浏览器。

### 第2步：工作台

展示：

- 首页轮播；
- 合同风险核查；
- 就业政策服务；
- 可信证据链；
- 当前工作区信息。

讲法：

“工作台不是单纯做一个表单，而是把三个阶段的用户旅程放在同一个平台。”

### 第3步：合同风险研判

操作：

1. 进入“合同研判”；
2. 选择文档语言；
3. 选择PDF页码范围；
4. 载入风险样例；
5. 选择材料和地区；
6. 运行可信研判。

重点展示：

- 风险分；
- 风险清单；
- 原文片段；
- 法源依据；
- 置信度；
- 规则、语义、模型候选标识；
- 待核实提示。

讲法：

“每条风险都要回答三个问题：原文是什么、依据是什么、下一步做什么。”

### 第4步：政策服务

操作：

1. 选择身份；
2. 选择地区；
3. 选择就业状态；
4. 勾选需要；
5. 匹配政策；
6. 查看条件、材料和官方入口；
7. 加入材料清单。

展示重点：

- 国家政策框架；
- 地区最低工资和属地入口；
- 地方标准待核验提示；
- 政策和证据链联动。

### 第5步：证据链

展示：

- 证据完整度；
- 事件时间线；
- 沟通问题；
- 投诉和仲裁材料草稿；
- 政策材料自动加入清单。

讲法：

“平台不让用户在发现风险后停在原地，而是继续给出证据和行动材料。”

### 第6步：可信评测

操作：

1. 进入“可信评测”；
2. 运行回归评测；
3. 展示风险召回率、法源覆盖率、无依据结论率和处理时间；
4. 展示两个模型的公平对照结果。

讲法：

“我们不只是展示成功案例，还保留了开发集、冻结留出集和失败案例。规则链在冻结留出集上的限制，正说明为什么需要大模型辅助和法源校验。”

### 第7步：系统说明

简要讲：

- 规则优先；
- 模型辅助；
- 人工复核；
- 数据来源；
- 隐私和权限。

### 第8步：管理后台（面试官主动问再展示）

操作：

1. 退出当前账号；
2. 登录管理员账号；
3. 展示用户、研判次数、高风险案例、风险分布和角色管理。

强调：

- 管理员与学生端完全分离；
- 不展示合同原文和个人敏感信息；
- 管理员密码由服务器环境变量控制。

## 八、面试官常见问题

### 为什么不直接用大模型做法律问答？

因为高风险场景需要可追溯、可验证和可拒答。大模型可以解释，但不能替代硬规则和法源校验。

### 大模型出错怎么办？

模型只能在允许的风险ID内提出候选，必须有原文依据；没有依据、置信度低或非法ID会被丢弃。

### 你们的独特价值是什么？

把合同风险、政策服务和证据链连接在一个平台里，并且把规则、法源、模型和人工复核分开。

### 没有真实用户怎么办？

当前是原型阶段。下一步会完成用户测试、法律抽样复核和地方政策核验。没有把未完成内容说成真实结果。

### 为什么做管理后台？

因为平台不仅服务用户，也需要管理用户、角色、研判记录和风险统计。管理员端和普通用户端分离。

## 九、不要说的话

不要说：

- “系统保证法律结论正确”；
- “系统可以替代律师”；
- “大模型自己判断所有风险”；
- “已经有很多真实用户”；
- “开发集100%就是真实准确率100%”。

可以说：

> 系统提供风险提示、政策信息和材料整理，不替代律师、仲裁机构或人社部门作最终判断。信息不足时会主动标记待核实。

## 十、演示结束总结

“职安盾 VeriWork 的核心不是把合同交给大模型，而是让规则负责硬约束、模型负责语义补充、法源保证可追溯、人负责边界和最终判断。平台把就业合同风险、政策服务和证据链串起来，让用户从发现问题走到准备材料和采取行动。”
