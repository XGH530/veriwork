# 大模型接入与对照指南

## 1. 配置后端模型

复制 `.env.example` 为 `.env`，填写：

```text
LLM_API_URL=https://provider.example/v1/chat/completions
LLM_API_KEY=your-key
LLM_MODEL=model-name
```

运行 `python server.py`。服务端会读取 `.env`，密钥不会发送到浏览器。

## 2. 模型在系统中的权限

模型可以：

- 在允许的13类风险ID内提出候选风险。
- 为已识别风险补充不超过120字的解释和行动建议。

模型不可以：

- 创造新的风险ID。
- 修改风险等级或权重。
- 新增不存在的法条。
- 在没有原文证据的情况下新增风险。

服务端会检查模型返回的原文片段是否真实出现在输入文本中，再为其绑定本地法源。没有原文依据、低置信度或非法ID会被丢弃。

## 3. 运行对照实验

纯模型基线：

```bash
python tools/evaluate_llm.py \
  --dataset data/holdout_cases_v2_frozen.json \
  --model model-name \
  --api-url https://provider/v1/chat/completions \
  --api-key-env LLM_API_KEY \
  --model-only \
  --output-prefix model_name_only
```

职安盾混合链：

```bash
python tools/evaluate_llm.py \
  --dataset data/holdout_cases_v2_frozen.json \
  --model model-name \
  --api-url https://provider/v1/chat/completions \
  --api-key-env LLM_API_KEY \
  --output-prefix model_name_veriwork
```

建议至少测试两个模型，并保留 API 返回原文、调用时间、模型版本和失败请求记录。

## 4. 人工测评

自动指标不能代替真实用户测试。至少记录：

- 用户是否发现规则命中之外的风险。
- 用户是否理解风险和依据的区别。
- 用户能否根据系统完成证据整理。
- 用户是否因为“待核实”提示而选择补充材料。
- 用户对隐私和模型使用的接受程度。

## 5. 答辩表述

可以说：

- 模型用于长尾语义召回和解释增强。
- 规则、法源和证据校验限制模型权限。
- 模型失败时会自动降级。
- 当前哪些模型结果已经实测，哪些仍待运行。

不可以说：

- 模型能够保证法律结论正确。
- 模型自己完成了全部风险判断。
- 未实测的模型分数是真实结果。
